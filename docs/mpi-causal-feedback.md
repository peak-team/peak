# MPI causal feedback

The MPI build provides an opt-in communication observer. It uses public MPI/PMPI calls and a separate nonblocking TCP channel driven by the existing heartbeat. It adds no launcher and does not change MPI messages, datatypes, reduction operators, or completion order. The default remains local control.

Set `PEAK_MPI_CAUSAL_FEEDBACK=1` in the existing job environment. Configure the same numeric `PEAK_MPI_OBSERVER_ADDRESS`, port `PEAK_MPI_OBSERVER_PORT`, and nonzero integer `PEAK_MPI_JOB_CONTEXT` on all participating ranks. `PEAK_MPI_OBSERVER_RANK` selects an existing world rank to host the parser, defaulting to zero. The address must be reachable from those ranks; no DNS or MPI metadata exchange occurs in application wrappers. Use the existing `PEAK_MPI_ACTIVATION_POLICY=post-init` where required by the target MPI stack.

With a positive existing heartbeat cadence, ranks without profiling targets still run the heartbeat service. Explicit `PEAK_HEARTBEAT_INTERVAL=0` remains disabled and is reported as global control unavailable. If strict hook mutation is unavailable, a positive cadence can service feedback with zero hook actions and an explicit absent-controller report. Local capture can retain immutable state before the first remote communication, but no client event exchange or global policy is activated by a self operation alone. An owner may listen while serving another active cohort. Missing channel configuration, unavailable feedback, or unknown membership cannot grant additional profiling budget.

Progress contracts are explicit implementation/configuration allowlists. An unsupported MPI configuration is reported as unknown and enters sticky coarse mode after communication. A timing experiment or an asynchronous-progress flag alone is not a capability proof. Intel fine mode requires `PEAK_MPI_PROGRESS_PROFILE=intel-2021.11-ofi-opx-host-async-v1`. Selecting it asserts host buffers and the reviewed OFI/OPX deployment. It requires the exact reviewed MPI version, `I_MPI_ASYNC_PROGRESS=1`, `I_MPI_FABRICS=shm:ofi` (or `ofi`), `I_MPI_OFI_PROVIDER=opx`, and `FI_PROVIDER` unset or `opx`. PEAK verifies the public asynchronous-progress MPI_T value at initialization; missing or conflicting evidence stays unknown. PEAK changes none of these settings. Default version/flag detection is conservative. The version-specific Intel MPI 2021.11 documented asynchronous profile covers its reviewed point-to-point and blocking collective families, plus Ibcast, Ireduce, and Iallreduce. Unreviewed families and unobservable active request free remain explicit coarse cases. Open MPI does not gain a fine contract merely by setting a progress option.

`PEAK_MPI_SINGLE_EXECUTION_FLOW=1` explicitly asserts eligibility for the reviewed blocking-collective slack rule. Leave it unset when independent workers, GPU work, asynchronous I/O, or other unjoined execution flows exist. Thread support level alone does not establish this property.

Memory is fixed before collection: each configured thread slot has a 256-record ring; definitions, requests, graph nodes, pending records, and transport queues have independent fixed capacities. `PEAK_MAX_NUM_THREADS` retains its existing meaning. `PEAK_MPI_REQUEST_CAPACITY` selects 16–65536 request slots, default 4096. `PEAK_MPI_COMPLETION_CAPACITY` selects 1–1024 completion scratch entries per thread, default 64. Exceeding a capture capacity never changes the native MPI call or expands storage in a wrapper; it invalidates fine analysis for that run.

The observer keeps raw local profiling and total costs separate from inherited delay. It publishes a cohort multiplier for future profiling demand and a covered global headroom estimate. Existing heartbeat hook selection, minimum calls, leases, and detach/reattach safety remain responsible for actual control. Feedback is asynchronous; reports include its quality and age, and unknown data is not interpreted as zero.

Reports identify the contract, coarse reason, raw L/P, covered event cut, policy mode, multiplier, event/loss counts, pending peak, observer CPU, traffic, feedback-age histogram upper bounds, and estimated budget-excess duration. The budget-excess estimate is not a wall-clock slowdown measurement. Finalization performs a bounded MPI-free drain without waiting for cross-rank closure. Storage referenced by wrappers is retained until process exit.

This integration remains subject to target-stack correctness, slowdown, and profiling-coverage validation. Coarse execution is an explicit fallback and does not establish fine-mode performance acceptance.

For measurement, `PEAK_HOOK_COVERAGE_METRICS=1` enables a separate optional final per-target row with confirmed physical attach/reattach/detach success counts and `attached_wall_seconds`, clipped to runtime start and the final snapshot. It adds no per-profile callback work or per-action I/O. Attached wall intervals differ from the existing collected invocation `total_s`; use both with independent eligible-call counts. Apply the same measurement-only patch to comparison arms when comparing these metrics.
