# MPI causal feedback

The MPI build provides an opt-in communication observer. It uses public MPI/PMPI calls and a separate nonblocking TCP channel driven by the existing heartbeat. It adds no launcher and does not change MPI messages, datatypes, reduction operators, or completion order. The default remains local control.

This candidate targets the existing `general_listener` CPU profiling cost producer and CPU heartbeat controller. The current qualification builds disable CUDA profiling. The host-buffer MPI deployment assertion does not establish coverage of CUDA or memory-profiler costs, and it does not assert a single application execution flow. Global budget coverage for those additional profiling producers is outside the current qualification scope until their actual cost counters are integrated and measured.

Set `PEAK_MPI_CAUSAL_FEEDBACK=1` in the existing job environment. Configure the same numeric `PEAK_MPI_OBSERVER_ADDRESS`, port `PEAK_MPI_OBSERVER_PORT`, and nonzero integer `PEAK_MPI_JOB_CONTEXT` on all participating ranks. Use a dedicated, unused observer port outside the hosts' ephemeral client-port ranges (for example, 20000 when the ephemeral range starts at 32768). This prevents a client from selecting the observer endpoint as its own source endpoint before the owner is listening. Give independent MPI jobs separate listener endpoints and job contexts. `PEAK_MPI_OBSERVER_RANK` selects an existing world rank to host the parser, defaulting to zero. The address must be reachable from those ranks; no DNS or MPI metadata exchange occurs in application wrappers. Use the existing `PEAK_MPI_ACTIVATION_POLICY=post-init` where required by the target MPI stack.

With a positive existing heartbeat cadence, ranks without profiling targets still run the heartbeat service. Explicit `PEAK_HEARTBEAT_INTERVAL=0` remains disabled and is reported as global control unavailable. If strict hook mutation is unavailable, a positive cadence can service feedback with zero hook actions and an explicit absent-controller report. Local capture can retain immutable state before the first remote communication, but no client event exchange or global policy is activated by a self operation alone. An owner may listen while serving another active cohort. Missing channel configuration, unavailable feedback, or unknown membership cannot grant additional profiling budget.

The owner settles a paired cut by following its continuations and live communication branches backward through all incoming dependencies, including candidate edges and shared cost owners. This avoids repeatedly solving unrelated future work while preserving old event values and complete frontier inputs. Root selection, projection, solving, restoration, and collection remain bounded background work; the application does not wait. Fixed owner storage increases by about 2.005 MiB with the current 128-rank capacities. The 256-record ring and existing byte/work quotas are unchanged. Local semantic and sustained-load tests do not establish native performance acceptance; qualification of this version on the target MPI stacks is still pending.

Progress contracts are explicit implementation/configuration allowlists. An unsupported MPI configuration is reported as unknown and enters coarse mode after communication. Capability, identity, metadata, sequence, and other hard faults remain sticky. Ring overflow is recoverable only after an eligible intra-communicator blocking S1 operation covers the managed MPI world and establishes a fresh graph epoch; currently this is Barrier or a qualified positive-count fixed-count Allreduce, Allgather, Alltoall, or Reduce_scatter family call. Until then capture stays coarse. Recovery does not grow the fixed ring or add application synchronization. A timing experiment or an asynchronous-progress flag alone is not a capability proof. Intel fine mode requires `PEAK_MPI_PROGRESS_PROFILE=intel-2021.11-ofi-opx-host-async-v1`. Selecting it asserts host buffers and the reviewed OFI/OPX deployment. It requires the exact reviewed MPI version, `I_MPI_ASYNC_PROGRESS=1`, `I_MPI_FABRICS=shm:ofi` (or `ofi`), `I_MPI_OFI_PROVIDER=opx`, and `FI_PROVIDER` unset or `opx`. PEAK verifies the public asynchronous-progress MPI_T value at initialization; missing or conflicting evidence stays unknown. PEAK changes none of these settings. Default version/flag detection is conservative. The version-specific Intel MPI 2021.11 documented asynchronous profile covers its reviewed point-to-point and blocking collective families, plus Ibcast, Ireduce, and Iallreduce. Unreviewed families and unobservable active request free remain explicit coarse cases. Open MPI does not gain a fine contract merely by setting a progress option.

The explicit Open MPI profile `ompi-5.0.5-ucx-1.17-rc-proto2-host-observed-v1` asserts the reviewed host-memory deployment, including UCX 1.17; its name is not automatic UCX runtime-version detection. The source review uses [Open MPI 5.0.5](https://github.com/open-mpi/ompi/tree/ca64c52a8227b4b3f3ee255a644ba4686ee9e600) and [UCX 1.17](https://github.com/openucx/ucx/tree/4ef9a097c12ee6f7a8d3e41c317ea2d47e424b32). Qualification receipts must identify the installed deployment corresponding to that review. The profile requires UCX PML, RC/self data transports, proto2, generic `UCX_RC_MLX5_TM_ENABLE=n`, and the verified fixed collective configuration. It retains communication cost intervals through successful public completion; buffered sends instead remain open through the application's successful `MPI_Buffer_detach`. Public buffer reuse, request completion, and progress closure are not interchangeable in general.

This Open MPI scope excludes user synchronous sends, unobserved active request free, unreviewed cancellation/error paths, variable-count collectives, RMA, partitioned requests and accelerator buffers. Fixed blocking Barrier on size 3 and non-power-of-two sizes 9–63 is excluded because the selected implementation uses synchronous-send tail paths. These restrictions are implementation-specific; they do not establish a complete graph from generic PMPI logs. Source-backed support is separate from successful target-runtime correctness, slowdown and coverage qualification.

`PEAK_MPI_SINGLE_EXECUTION_FLOW=1` explicitly asserts eligibility for the reviewed blocking-collective slack rule. Leave it unset when independent workers, GPU work, asynchronous I/O, or other unjoined execution flows exist. Thread support level alone does not establish this property.

Memory is fixed before collection: each configured thread slot has a 256-record ring; definitions, requests, graph nodes, pending records, and transport queues have independent fixed capacities. `PEAK_MAX_NUM_THREADS` retains its existing meaning. `PEAK_MPI_REQUEST_CAPACITY` selects 16–65536 request slots, default 4096. `PEAK_MPI_COMPLETION_CAPACITY` selects 1–1024 completion scratch entries per thread, default 64. `PEAK_MPI_OBSERVER_WORK_BUDGET` fixes the per-heartbeat observer work quota at startup: decimal integer 1–1048576, default 16384. Invalid values emit one initialization diagnostic and use 16384. Later environment changes do not alter the quota. Reports include `work_budget` and `configured_slots` for provenance. This is a bounded backend work-step quota, not CPU-seconds or a slowdown/profiling budget; observer CPU and wall time remain subject to cost accounting and performance acceptance. Failures from the earlier 8192-quota 144/192-slot replay remain historical comparisons and do not characterize the 16384 default. A ring overflow records loss and pauses fine capture without changing the fixed 256-record capacity. Raw costs and loss counters continue to be retained. Recovery does not modify native MPI messages or requests; surviving frontend request descriptors follow their ordinary MPI lifecycle. The old observer graph and message nodes are discarded, so prior dependencies are represented approximately from the fresh cut. At an eligible managed-world blocking S1 operation, a fresh graph epoch may resume without waiting in an application wrapper or adding synchronization. Because prior event history was lost, feedback remains approximate and does not restore `COMPLETE`; only fresh available `q/g` pressure and existing local headroom/lease checks may inform later reattach. Stale feedback never relaxes reattach, and incomplete global risk remains unknown/unavailable. Exceeding other hard capacities remains sticky coarse. The native MPI call and its arguments, messages, datatype, operator, and completion order are not changed by capture loss.

`PEAK_MPI_OBSERVER_OWNER_BYTE_BUDGET` fixes the owner’s shared transport/capture allowance per service turn at startup: decimal integer 1–16777216, default 65536. Invalid values produce one initialization diagnostic and fall back to 65536. Clients always retain 65536. The owner is selected by the existing `PEAK_MPI_OBSERVER_RANK`; reports show `configured_owner_byte_budget` and each rank’s `effective_byte_budget`. This allowance includes local capture charges and socket IO; it is not the measured network traffic counter or a CPU-time budget. It changes neither memory capacities nor the profiling target. Later environment changes do not alter it.

On Linux, optional `PEAK_MPI_OBSERVER_CPU` places the selected parser owner's existing heartbeat thread on one logical CPU. Reserve that CPU within the job allocation before setting this decimal CPU number; PEAK does not select or reserve a core. Application threads and other ranks retain their affinity. Unset, invalid, or unavailable settings retain existing affinity, with invalid/unavailable settings diagnosed once. The control report records requested/effective CPU (`-1` means no explicit binding). This setting does not remove observer costs from raw accounting or guarantee a global slowdown target.

The current 128-rank experiment uses `PEAK_MPI_OBSERVER_OWNER_BYTE_BUDGET=2097152`, `PEAK_MPI_OBSERVER_WORK_BUDGET=262144`, and an explicitly reserved observer CPU. This recipe remains experimental until target MPI correctness, observer wall-time overhead and same-budget profiling coverage pass native qualification. The default 65536/16384 configuration is not qualified for the 128-rank target. No automatic world-size scaling is applied.

Immutable communicator definitions are sent from a bounded published slab prefix before records that reference them. Producer prefixes are frozen before the definition high-water is read; ongoing publication cannot make a batch chase new objects indefinitely.

Raw `L` retains every local profiling, synchronous observer, startup, control and heartbeat management fee. MPI feedback uses a separate application cost `A = P + synchronous producer-observer + startup + control`; the existing heartbeat worker's measured management CPU is excluded from `A`, propagated `D`, pressure and global headroom. No new worker thread or execution-flow graph is introduced. A single snapshot reads these counters coherently and derives `L = A + heartbeat management`; reports retain both totals and the excluded heartbeat amount. Synchronous producer work, including finalization work charged to its producer, remains billable. A single authoritative integer P/A/L cut is formed by checked sums of separately quantized components. Event, RAW, recovery, policy and feedback paths retain those cuts; idle/recovery copies them, and differences are taken before conversion to seconds. Floating aggregate subtraction is never used to reconstruct a cut. Raw floating cost statistics remain unchanged. Annotated event, RAW, recovery and feedback cuts retain named A values; absent annotations conservatively use raw L, and invalid annotations cannot establish zero cost. The versioned observer channel rejects incompatible wire formats.

The observer keeps raw local profiling and total costs separate from inherited delay. It publishes a cohort multiplier for future profiling demand and a covered global headroom estimate. Existing heartbeat hook selection, minimum calls, leases, and detach/reattach safety remain responsible for actual control. Feedback is asynchronous; reports include its quality and age, and unknown data is not interpreted as zero.

Reports identify the contract, coarse reason, raw L/P, covered event cut, policy mode, multiplier, event/loss counts, pending peak, observer CPU, traffic, feedback-age p50/p95/p99 histogram upper bounds and maximum observed at heartbeat samples, the profile/control/management/producer-observer/startup cost breakdown, and estimated budget-excess duration. The budget-excess estimate is not a wall-clock slowdown measurement. Finalization performs a bounded MPI-free drain without waiting for cross-rank closure. Storage referenced by wrappers is retained until process exit.

This integration remains a qualification candidate; CI and component results do not establish target runtime acceptance. The current comparison scope is native, main local control, and PR134. High-rate synthetic communication stress runs are retained as stress comparisons, not representative-workload performance gates. Target MPI correctness, slowdown, and profiling coverage still require their own evidence; no acceptance is claimed here.

For measurement, `PEAK_HOOK_COVERAGE_METRICS=1` enables a separate optional final per-target row with confirmed physical attach/reattach/detach success counts and `attached_wall_seconds`, clipped to runtime start and the final snapshot. It adds no per-profile callback work or per-action I/O. Attached wall intervals differ from the existing collected invocation `total_s`; use both with independent eligible-call counts. Apply the same measurement-only patch to comparison arms when comparing these metrics.
